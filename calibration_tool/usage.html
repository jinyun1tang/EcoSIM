EcoSIM Calibration Tool — Usage Guide

An agent-based reinforcement-learning-style framework for calibrating EcoSIM parameters against observation targets, orchestrated entirely through the canonical skill scripts in python_tools/.agents/skills/. No skill logic is reimplemented here.

1. Architecture

calibration_tool/
├── env.py                    # gym-style environment: reset() / step(theta)
├── run.py                    # CLI entry point
├── agent/
│   └── random_search.py      # baseline agent (reference benchmark)
├── cases/
│   └── biocrust/config.json  # dryland case: parameters, bounds, targets
├── runs/                     # per-episode scratch dirs (gitignored)
└── usage.html                # this file

Each step(theta) executes one full calibration cycle in an isolated episode directory:

  1. Reset / clone — copy the pristine case from examples/run_dir/biocrust; delete restart files and stale history output so every episode cold-starts identically.
  2. Localize parameters — copy the shared input_data/ecosim_pftpar_*.nc into the episode and repoint pft_file_in in the namelist. The shared file is never modified.
  3. Absolutize paths — rewrite relative *_in and prefix namelist entries against the original run dir, since the clone lives elsewhere in the tree.
  4. Apply parameters — mutate only the target PFT record (lich22 for the biocrust case) via ParamEditor.py from the ecosim-pftpar-editor skill; all other PFT records remain untouched.
  5. Run the model — invoke the executable with the namelist as argv[1] (required by drivers/ecosim/ecosim.F90).
  6. Extract targets — run the ecosim-h0-target-extractor skill script on the episode's h0 output (GPP, ET, LAI, biomass, canopy height, …).
  7. Score — reward = negative weighted normalized RMSE against the observed targets in the case config.

2. Prerequisites

  • Built executable: local/bin/ecosim.f90.x.
  • Python environment with numpy, netCDF4, pandas (used by the skill scripts): 
    python3 -m venv calibration_tool/.venv
calibration_tool/.venv/bin/pip install numpy netCDF4 pandas
  • The python_tools/ submodule checked out alongside.

3. Running a calibration

# from the repository root
calibration_tool/.venv/bin/python -m calibration_tool.run \
    --case calibration_tool/cases/biocrust/config.json \
    --budget 20 --agent random

The runner writes every evaluated parameter set, reward, and extracted target to calibration_tool/runs/search_history.json and prints the best result. Episode directories are pruned automatically to the last keep_last_n.

4. Configuring a case (config.json)

FieldMeaning
source_run_dirCase directory to clone each episode from (relative to the case config).
ecosim_exePath to the built model executable.
pythonInterpreter used for skill scripts (venv python with netCDF4).
pft_codeSix-character PFT record to calibrate, e.g. lich22.
parametersList of PFT-parameter variable names with bounds [min, max] and optional log sampling. Actions outside bounds are rejected before any simulation is spent.
targetsObservation targets keyed by h0-extractor metric names (annual_gpp, annual_et, midseason_lai, …), each with observed, weight, and units in note.
timeout_s / keep_last_nPer-run timeout and episode directory retention.

5. Extending the agent

RandomSearchAgent is the reference benchmark: any smarter agent (Bayesian optimization / TPE surrogate, or an agentic loop that reads the sanity-check and target diagnostics as text observations and invokes skills) must beat it at equal simulation budget. An agent only needs two methods:

6. Current status and known limits

  • End-to-end step() verified for the biocrust case: cloning, path handling, parameter editing, model execution, and target extraction all run; a 10-year simulation takes several minutes.
  • Target values in cases/biocrust/config.json are placeholders equal to the baseline simulation — replace them with real site observations before drawing any scientific conclusion.
  • The action space must contain only continuous, per-PFT numeric parameters. Discrete configuration (PFT codes, Koppen settings, grid mode) is fixed per case and intentionally excluded from calibration.
  • Each episode is an independent directory, so episodes can be executed in parallel; keep_last_n pruning and the runs directory placement must be respected when parallelizing.
Guardrails. Never point source_run_dir at a directory containing results you cannot afford to lose: episodes delete restart and history files inside their own clone only, but the model executable writes outputs relative to its working directory. The framework never writes to the shared input_data/ or to the original case directory.
